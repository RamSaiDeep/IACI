# Codebase notes (stage 1)

## Framework
- `frontend/` is a Next.js 16 (App Router) + React 19 + Tailwind 4 app, React Compiler on. `frontend/AGENTS.md` warns Next 16 differs from older versions; route handlers still use the standard `export async function POST(req: Request)` shape (see `src/app/api/visitors/route.ts`).
- Fonts: Poppins (`--font-poppins`) + Geist Mono. Palette: navy `#0b2b5f` foreground, orange accent `#f26a21`, cream background `#fcfcfa`. Tailwind tokens: `bg-background`, `text-foreground`, `bg-accent`, `bg-surface`, `bg-surface-muted`, `shadow-card`.
- `backend/` is the Python pipeline (xarray/zarr → JSON). It is read-only for this feature.
- There is **no test runner** in the repo. This work adds `vitest` as a dev dependency.

## Routing
- `/` global home, `/about`, `/india`, `/india/about`, `/explore`, `/analyze` (India), `/uk/*`, `/nepal/*`. The new page is `/ask`.
- `components/Header.tsx` has a `PORTALS` table + `GLOBAL` nav. `/ask` is not under a portal so it falls to `GLOBAL`; one nav entry is added there.
- `components/Footer.tsx` is rendered by the root layout.

## Data storage and serving
All index data is **static JSON in `frontend/public/data`**, generated by the Python pipeline and fetched by the browser. There is no database. Format (compact):

```
{ "fields": ["IACI","DS","PS","SS","T10S","T90S","W"],
  "rows":    [[YYYYMM, v1, v2, ...], ...] }            // country.json
{ "fields": [...], "regions": { "NAME": [[YYYYMM, ...], ...] } }
```
Values are monthly **standardized anomalies (z-scores)** against 1991–2020, per calendar month. `null` = not measured (SS inland).

| Country | Files | Levels | Fields |
|---|---|---|---|
| India | `india/country.json`, `india/state.json`, `india/district/<state_slug>.json` | country > 36 states/UTs > 782 districts | IACI, DS, PS, SS, T10S, T90S, W |
| UK | `uk/country.json`, `uk/nation.json`, `uk/county_ua/<nation_slug>.json` | country > 4 nations > 218 counties/UAs | UKACI + same six |
| Nepal | `nepal/country.json`, `nepal/province.json`, `nepal/district/<province_slug>.json`, `nepal/local/<district_slug>.json` | country > 7 provinces > 77 districts > 777 local levels (keyed by id) | NACI, DS, PS, T10S, T90S, W (**no SS**) |

- `data/countries.json` is the manifest: fields, levels, `periods.first/last` (India/Nepal 1991-01 → 2026-06, UK → 2026-09). A `demo: true` flag marks synthetic data (none currently set).
- `data/districts/*` and `data/india_data.json`/`state_data.json` are legacy copies of `india/*` (byte-identical).
- Region keys are upper-cased names. Parent→child files are named with `slugifyState(parent)` (`lib/climate.ts`).
- Boundaries: `public/geojson/<country>/...` (India: `geojson/india/district/<state>.json`, feature props `{name, district, parent}`; UK `{name, county_ua, parent}`; Nepal `{name, district, parent}`).

## Existing front-end code worth reusing
- `lib/climate.ts`: `Field`, `Values`, `periodOf/yearOf/monthOf`, `slugifyState`, `normalizeName`, `toSeries`, `toRegionSeries` (pure; usable on the server).
- `lib/indicators.ts`: `INDICATORS` (labels/accents), `severityOf`, `formatValue`, `colorForValue`, `SCALE_GRADIENT`.
- `lib/trend.ts`: `buildTrend` (60-month trailing mean). Used for charts.
- `components/TrendChart`, `RegionMap`, `IndiaMap`, `ScaleLegend`, `Header`, `Footer`. `d3-geo` is the only chart/map lib (hand-rolled SVG); there is no charting package.
- Existing indicator UI names are "Hot Extreme", "Dry Spell"... The Ask UI uses the plain-language names required by the brief (see decisions).

## Where the tool layer reads from
Server-side `fs` reads of `frontend/public/data/**` (resolved from `process.cwd()`), parsed with the existing `toSeries`/`toRegionSeries`, cached in module memory. `next.config.ts` gets an `outputFileTracingIncludes` entry so the JSON ships with the `/api/ask` serverless function on Vercel.

## Gaps found
1. **Trends are not precomputed**: Sen's slope and Mann-Kendall are implemented fresh (`lib/ask/stats.ts`). The 60-month moving average in `trend.ts` is only a smoother.
2. **No neighbour lookup**: neighbours are derived from GeoJSON (shared/near-shared boundary vertices, grid-hashed) with a nearest-centroid fallback.
3. **No place-name index / aliases**: built at runtime from the data files; a small alias table covers renamed districts (Gurgaon/Gurugram, Bombay/Mumbai, Madras/Chennai...). District names are *not unique* inside a country, so place ids include the parent.
4. **No data for "annual" values**: annual values are the mean of the 12 monthly anomalies (documented). Season windows (monsoon = Jun–Sep, summer = Mar–May, etc.) are defined in code.
5. The index is not published as raw (un-standardized) values, so all comparisons are on anomalies by construction.
6. Index version string is not in the data. "IACI Draft 1.0" is taken from the existing site copy (the home page marks India Draft 1.0).
